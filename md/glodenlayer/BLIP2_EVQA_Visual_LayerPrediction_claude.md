## 7. 关键观察

1. **E-VQA 与 Bridge30 数据集的 visual cos 几何不同**：E-VQA 浅层 |cos|≈0.13 显著大于 Bridge30 浅层的 |cos|≈0.01–0.04，这导致 `M_abscos_x_newn` 峰值从 Bridge30 的中层（13–15）整体前移到 E-VQA 的浅层（0–3）。
2. **Locality 预测在两个数据集间高度迁移**：`S_v_new_norm` 反排在 E-VQA 仍指向最深层（30, 29, 28），与 Bridge30 几乎相同；说明"梯度幅度最弱的层 = locality 最好"这一规律对数据集 robust。
3. **Average 与 Locality 高度重合**：因 request 是 sanity 平台、generality 变化幅度小于 locality，average 仍被 locality 主导。
4. **Generality 推荐 layer 0 的可信度**：Bridge30 BLIP2 visual 上 `M_abscos_x_newn` rho 仅 0.464（中等强度，Top3=13,15,14 命中真实 Gen 平台 layer 15），属于"弱-中等可预测"。E-VQA 由于浅层 cos 已经很大，Top1 直接落在 layer 0，建议在实际编辑实验时同时尝试 Top3=`{0, 1, 3}` 与 BLIP2 Bridge30 经验区间 `{13, 15, 14}` 做对照。

## 8. 实用建议

- **Locality / Average 编辑**：直接取 layer 30（次选 29、28）。
- **Generality 编辑**：优先 layer 0，但需要真实 sweep 验证；若 layer 0 效果不佳，回退到 Bridge30 经验区间 layer 12–16。
- **Request**：保持当前请求层无需 LGA 干预（≈1.0 已饱和）。
- **跨数据集迁移注意**：`S_v_cos` 符号和量纲会随训练数据/编辑目标变化，`M_abscos_x_newn` 的 Top 层位置不稳定；而 `S_v_new_norm` 反排在不同数据集间表现稳定，是更可靠的跨场景指标。

### 9.3 三条根因

**根因 1：Bridge30 的 Request≈1.0 sanity 平台不能外推到真实编辑**

Bridge30 是 request-only adapter + EMA loss + train=test 同源，使 Request 在所有有效层都钉死≈1.0。我于是把 Combined3 当成 Locality + Generality 的两元平均，并发现 Loc 变化范围最大→Combined3 被 Loc 主导→`new_norm` 反排 rho=-0.765。

但真实 E-VQA 编辑里 **Request 自身在层间剧烈变化（95.10→86.22，幅度 12.6 个百分点）**，比 M-Loc 变化幅度（84.51→92.30，7.8 pt）还大。Average 此时是**三轴联合驱动**，Locality 主导假设根本不成立。Bridge30 推得的"Average 与 Locality 高度重合"在真实编辑场景下是伪命题。

> **MEMORY 验证**：`feedback_bridge30_request_sanity_axis.md` 的"不要把 request 纳入多轴 agg"约束本意是防止把假信号当真，但反过来也意味着——**用 Bridge30 推的 agg 公式不能直接迁移到 Request 真有变化的真实编辑实验**。这次踩的就是这个坑。

**根因 2："梯度幅度最弱 = Locality 最好"在极深层失效（编辑根本写不进去）**

`S_v_new_norm` 反排在 Bridge30 上 rho=-0.699 看似稳定，但它只刻画了"扰动小"，没有刻画"编辑能不能进得去"。在 layer 30，`S_v_new_norm`=0.0885（仅为 layer 19 的 17.5%）、`S_v_cos`=**-0.0265（负值）**，意味着：

- 梯度方向与编辑目标**反对齐**（cos<0），向这个方向走反而远离目标
- 梯度幅度太弱，编辑信号传不过去 → 真实结果 Rel 直接掉到 86.22

**反排 metric 没有下界保护**——它只挑"最弱"，不挑"够用的最弱"。

**根因 3：Generality Top1=0 的几何错觉**

E-VQA 浅层 `S_v_cos`≈0.13 远高于 Bridge30 的 0.01–0.04，导致 `M_abscos_x_newn` = |cos|×new_norm 在 layer 0 处达到峰值 0.1175。但**浅层高 cos 是因为 token embedding 表层就和编辑文本天然相似（lexical overlap），不代表此处编辑会泛化**。真实 Generality 是单调递增到 layer 19 才回落（94.43→97.90→83.62），需要"足够深的语义抽象层"才能形成可迁移的编辑表征。

`M_abscos_x_newn` 在 E-VQA 上**单调递减**，不存在峰值——任何"取 Top"的策略都会落在 layer 0。

### 9.4 修正：从"取极值"到"找拐点"

观察 E-VQA BLIP2 visual 的层间几何：

| 区间 | S_v_cos 趋势 | S_v_new_norm 趋势 | 几何特征 |
| --- | --- | --- | --- |
| 0–17 | ≈0.13 平台 | 0.89→0.59 缓降 | 高对齐 + 高幅度（**容量过剩**） |
| **18–22** | 0.125→0.096 **快速下降** | 0.55→0.35 中等 | **cos 拐点 + new_norm 中段** |
| 23–27 | 0.05→0.016 急降 | 0.31→0.17 偏低 | 对齐快速丢失 |
| 28–30 | **负值** -0.031→-0.027 | 0.13→0.09 极弱 | **方向反转 + 容量不足（编辑死区）** |

**Layer 19 正好坐落在 cos 拐点（the "elbow"）上**，对应"梯度方向尚保持正对齐，但容量不再过剩"——这是 OPT decoder 中**功能层最后一次具备编辑能力**的位置。

### 9.5 修正后的推荐公式（pos-cos-elbow rule）

新公式 `M_edit_sweet`：

```
有效层判据：S_v_cos > cos_min（建议 0.08）AND S_v_new_norm > norm_min（建议 0.30）
评分：M_edit_sweet(l) = -|S_v_cos(l) - S_v_cos(l+1)|     # cos 单调递减时取最大跌幅前的层
        或等价：argmax_l { S_v_cos(l) - S_v_cos(l+k) }   # k=2~3，找 cos 拐点
```

直观解释：

1. **必要门槛**：cos>0 保证方向对齐，new_norm>下界保证编辑能写进去（排除 layer 23–30 死区）
2. **拐点定位**：在过滤后的层里找 cos 即将塌陷的最深层——这是"还能编"的最深位置，对应论文中 OPT 中后段的语义抽象峰

应用到 E-VQA 数据：

| Layer | S_v_cos | S_v_cos(l)–S_v_cos(l+2) | 是否过门槛 | M_edit_sweet 排名 |
| ---: | ---: | ---: | --- | ---: |
| 17 | 0.1287 | 0.0042 | ✓ | — |
| 18 | 0.1246 | 0.0098 | ✓ | — |
| **19** | **0.1148** | **0.0146** | ✓ | **Top1** |
| 20 | 0.1002 | 0.0024 | ✓ | — |
| 21 | 0.0977 | 0.0019 | ✓ | — |
| 22 | 0.0958 | 0.0469 | ✓ | Top2（拐点真正发生在 22→23）|
| 23 | 0.0489 | 0.0178 | ✗（cos<0.08）| 排除 |

**Top1 = layer 19**（cos 在 19→21 累积下降 0.0146，是过门槛区间内 cos 最早大幅松动的层），与论文实测一致。Top3 推荐 **{19, 20, 18}** 或保守扩展 **{18, 19, 20, 22}**。

### 9.7 与 Bridge30 推荐公式的关系

| 公式 | Bridge30 上的 rho | E-VQA 实测命中 | 失效原因 |
| --- | ---: | --- | --- |
| `M_abscos_x_newn` 降序（Gen）| +0.464 | ✗ Top1=0 偏浅 | E-VQA 浅层 cos 异常高，metric 单调递减 |
| `M_new_norm` 反排（Loc/Avg）| -0.699 / -0.765 | ✗ Top1=30 反向 | 极深层 cos<0 + 编辑死区，反排无下界 |
| **`M_edit_sweet`（拐点+门槛）** | **未在 Bridge30 上拟合** | **✓ Top1=19** | — |

Bridge30 的两个公式在 Bridge30 自身验证集上 rho 显著，但都是**线性单调假设**（取极值）。真实编辑曲线是**单峰**（既怕浅又怕深），需要拐点检测而非极值排序。

### 9.8 实用建议（更新版，覆盖原 §8）

1. **首选**：layer **19**，次选 **18 / 20 / 15**（论文实测 layer 15 的 Average=96.89 已经接近 layer 19 的 97.53，是稳健备选）
2. **明确避开**：layer 25 以后（Average 大幅下降）、layer 28–30（cos<0 编辑死区）
3. **跨数据集启示**：把 Bridge30 推得的"取极值 + agg 主导"公式当作 prior，而非最终决策；真实编辑前必须确认 Request 是否会随层变化——如果会，单峰拐点 metric 优于极值反排
4. **公式简化版（实操可用）**：在 cos>0 且 cos>0.5×max(cos) 的层中，取最深的一层。该规则在 E-VQA BLIP2 visual 上指向 layer 21–22，与 layer 19 偏差 2–3 层，仍在 Top3 区间

### 9.9 局限

- `M_edit_sweet` 仅在 1 个数据集（E-VQA）+ 1 个模型（BLIP2-OPT-2.7B）上事后验证，cos_min/norm_min/k 的取值未经过其他数据集回归
- 拐点检测对噪声敏感：当 cos 曲线接近平台时，argmax-差分 容易跳层
- 适用前提：cos 曲线存在明显单调下降段。若数据集是 InstructBLIP 那种"浅层 cos 就高且无明显下降"的情形，本方法仍会失效——需保留 `M_abscos_x_newn` 作为 InstructBLIP 类的备选 prior
