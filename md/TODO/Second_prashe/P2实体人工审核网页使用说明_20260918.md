# P2实体人工审核网页使用说明（2026-09-18）

## 用途

对P2固定seed选取的50条MMKE-Entity记录执行独立人工审核，确认每条记录的稳定主体Q-ID。网页同时展示图片、官方原始文本上下文、原搜索候选和建议候选，并将每次判定立即保存到项目文件。

## 图片角色

- **`image`**：官方记录的主编辑/可靠性图。第一阶段真实加载器把它与`src`和完整`alt`组成编辑请求。
- **`image_rephrase`**：官方记录的图像泛化测试图。它使用同一`src`和完整`alt`，检查编辑能否泛化到另一张图。
- **非官方同名参考图**：本审核工具从服务器MMKE实体图片库按主体名额外匹配，仅用于辅助辨认主体。50条中43条有同名参考图；它们不属于当前JSON记录，不进入训练或评测，也不要求逐张标注Q-ID。
- **locality图**：用于局部性评测，不参与主体Q-ID判定。

MMKE论文把视觉实体编辑定义为：用同类型的另一实体图像替换原实体图像，并对关键描述作反事实修改；图像泛化再用同一对象的另一张图检验编辑结果。论文：<https://arxiv.org/html/2502.19870>。本项目第一阶段真实加载器`code/data/vllm_dataset.py`第70–78行与该角色划分一致。

页面引用的259张图片已从服务器 `MMKE-Bench/data_image` 按原始相对路径复制到本地；引用缺失数为0。

## 审核规则

综合以下信息确认主体Q-ID：

1. `alt`第一句的主体名称；
2. `type_self`；
3. `pred`中的学名、出生日期、成员或其他唯一身份信息；
4. 建议Q-ID的Wikidata标签和描述；
5. 必要时展开非官方同名参考图作辅助。

`pred`是MMKE数据集固定的编辑前知识描述，不是BLIP-2、LLaVA或MiniGPT-4对`src`的现场回答。

审核按钮只回答“建议Q-ID是否对应`alt`所指主体”。不要判断主编辑图或泛化图是否真实展示该Q-ID，也不要给每张非官方参考图分别标Q-ID。

- 建议Q-ID正确：点“正确”，页面自动使用建议Q-ID。
- 建议Q-ID错误：点“错误”，填写正确Q-ID和原因。
- 无法确定：点“不确定”，在备注中说明缺少的证据。

## 保存与收集

- 每次判定立即原子写入 `review_app/data/review_annotations.json`。
- 页面刷新或服务重启不会丢失已保存标注。
- “导出”按钮在 `review_app/data/exports/` 产生带时间戳的CSV和JSON。
- 审核完成后，由Codex读取已保存标注，计算准确率、产生审核摘要，并在通过门槛后才扩展到636条。

### 追加审核时如何理解 `pred`、`alt` 和图片

- `pred`是数据集固定的原始实体知识描述，不是某个BLIP-2、LLaVA或当前模型对`src`的现场回答。
- `alt`是编辑后的目标文本。对MMKE-Entity，主体通常仍是`pred`所述实体，但作者会故意把主体的若干关键属性改为反事实内容；这些“错误事实”正是要写入模型的编辑目标。
- `image`和`image_rephrase`是作者用同一大类中的另一实体图片替换得到的反事实视觉输入。它们按协议本来就可以与`alt`中命名的主体不一致。
- 人工Q-ID审核只确认`alt`中被命名的主体身份。不要因为`alt`属性不符合现实，或因为图片显示另一个实体，就否定主体Q-ID。
- 例如官方索引53：图片文件是`Spider-Man+2.jpg`和`Spider-Man+11.jpg`，`pred/alt`主体是绿灯侠John Stewart；`alt`里的Marvel、Jack Kirby、Stan Lee、Native American等内容是故意构造的反事实属性。该主体应链接到Wikidata `Q2556873`，而不是同名歌手。

完整核验证据见同目录的`MMKE-Entity_pred_alt_image语义核验_20260918.md`。

67条中已经发现真实同名歧义，例如`John Stewart`曾连到同名歌手、`Monticello`曾连到佛罗里达城市，因此不能将这些记录自动接受。追加审核全部完成后才能冻结636条主体身份、重建P1连通分组并重划dev集合。
