# 第二阶段KG增强设计：真实基础图与反事实编辑覆盖层

日期：2026-09-18

## 结论

研究目标“利用知识图谱增强编辑后模型的泛化性”与MMKE-Entity兼容；不兼容的是“直接把目标实体的现实真实图谱作为编辑后图谱”这一实现方式。

MMKE-Entity的`alt`是反事实编辑目标。若直接检索并注入Wikidata中的现实事实，图谱会与`alt`冲突，可能把模型拉回`pred`。应采用动态双层图：

```text
G_real：Wikidata等来源的现实基础图
Δ_edit(sample_id)：从pred→alt提取的反事实事实变更
G_edit(sample_id) = G_real ⊕ Δ_edit(sample_id)
```

`G_edit`只在当前编辑样本或编辑请求作用域内生效，不覆盖全局真实图谱。

## John Stewart示例

稳定主体身份：

```text
Q2556873 — John Stewart，DC Comics的Green Lantern
```

现实基础图包含DC Comics、Dennis O'Neil、Neal Adams、Sidney Poitier、Phil LaMarr等现实联系。

当前样本的反事实覆盖层包含：

```text
John Stewart --published_by--> Marvel Comics
John Stewart --created_by--> Jack Kirby
John Stewart --created_by--> Stan Lee
John Stewart --design_based_on--> Denzel Washington
John Stewart --voiced_by--> Kevin Conroy
John Stewart --represented_ethnicity--> Native American
```

这些边必须标记为`counterfactual`，并绑定该样本的`sample_id/edit_context_id`。Spider-Man图片与John Stewart的对应也只能记录为当前编辑上下文的视觉映射，不能写入全局真实图谱。

## 为什么真实图谱仍然有用

图谱的作用不是否定`alt`，而是为反事实新对象提供真实的后续关系。John Stewart样本的`port_new`询问：其设计所基于的人出生于哪一年。推理链为：

```text
John Stewart --design_based_on--> Denzel Washington   # alt提供的反事实编辑边
Denzel Washington --birth_year--> 1954                # 真实基础图中的事实边
```

因此答案是1954。第一跳采用反事实编辑，后续跳采用真实KG。这正是知识图谱增强编辑泛化与Portability的合理切入点。

## 与GLAME的对应

GLAME将编辑表示为`(s,r,o,o*)`，从新对象`o*`及其高阶邻居构建编辑后的关联子图，再把图结构融入模型编辑。MMKE自由文本需要先增加一层适配：

1. 链接`pred/alt`的稳定主体Q-ID；
2. 对比`pred`和`alt`，抽取旧事实与新事实；
3. 链接新对象Q-ID或保留文字/数值节点；
4. 从新对象检索真实的1-hop/2-hop邻居；
5. 构建带`counterfactual`与`real`来源标签的样本级动态子图；
6. 将该子图编码后输入Adapter编辑过程。

GLAME来源：https://aclanthology.org/2024.emnlp-main.1261.pdf

## 图谱有效性的判据

仅能回答训练时给出的`alt`，只能证明编辑可靠性或记忆成功，不能单独证明知识图谱有用。至少需要与无图谱的Ours-Direct进行同协议比较：

- Reliability：`image + src -> alt`；
- Text Generality：`image + rephrase -> alt`；
- Image Generality：`image_rephrase + src -> alt`；
- Direct edited-fact QA：`rel_1/rel_2`及`m_rel_1/m_rel_2`；
- Portability：`port_new`，重点检验“反事实编辑边 + 真实邻接边”的推理；
- Locality：无关文本和图片在编辑前后保持稳定。

证明KG有效需要：图谱方法相对Ours-Direct在未直接训练的泛化/Portability问题上提高，同时不明显损害Reliability和Locality。还应做以下消融：

- 无KG；
- 仅现实KG，不加反事实覆盖；
- 仅反事实直接边（0-hop）；
- 反事实边 + 新对象真实1-hop；
- 反事实边 + 新对象真实2-hop；
- 打乱邻居或错误Q-ID负对照。

## 对当前P2/P3的影响

- 当前主体Q-ID人工审核仍然必要，因为它提供稳定主体锚点。
- P2不能止于主体Q-ID；后续需要提取`pred→alt`事实差异并链接新对象。
- `alt`中的反事实不应写回或污染全局Wikidata缓存。
- 第一阶段真实代码尚未接入`rel_*`、`m_rel_*`和`port_new`；若要证明KG提升关联泛化，第二阶段必须补齐这些评测入口。
- 如果研究坚持“所有图中边都必须是现实真值”，则MMKE-Entity不适合作为唯一主数据集，需要另建真实事实更新数据轨；但仍可保留MMKE作为标准反事实基准。
