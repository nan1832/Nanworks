## 2. 整体研究问题

本研究面向视觉语言模型知识编辑，采用“先定位、再编辑”的两阶段路线。

### 2.1 第一阶段：编辑层定位

冻结视觉语言模型主体，在语言解码器不同层的视觉 token 位置插入视觉-only Adapter，并通过低成本定位方法预测 Top-K 候选插入层；再对候选层执行真实 Adapter 训练，以可靠性、泛化性和局部性验证候选层质量。

### 2.2 第二阶段：知识图谱增强编辑

固定第一阶段得到的候选层，在该层引入两类视觉表征增量：

- 目标知识注入模块：从编辑提示中提取与目标新知识直接相关的信息，并生成视觉 token 增量；
- 相关知识注入模块：围绕编辑目标构建外部知识子图，使用图神经网络编码关联实体和关系，并将图谱增量注入视觉 token。

融合后的视觉表征继续输入冻结解码器后续层，使模型既能回答编辑目标问题，也能将编辑知识用于关联问题。

## 3. 第一阶段已确认事实

### 3.1 实验对象

- 数据集：E-VQA/pilot500、MMKE-Visual、MMKE-Entity；
- 模型：BLIP2-OPT-2.7B、InstructBLIP-Vicuna-7B、MiniGPT-4-Vicuna-7B、LLaVA-v1.5-7B、Qwen2.5-VL-3B-Instruct、PaliGemma-3B、SmolVLM-Instruct-1.7B；
- 正式定位方法：Middle-Prior、VisEdit、SaLEM、LGA、Perturb-KL、CMA和Ours-Direct；
- Adapter插入在语言解码器层的视觉 token 表征位置；包含Q-Former的模型也不把Q-Former层混入语言解码器层排序。

### 3.2 Ours-Direct正式主公式

主公式已固定为：

\[
M_{\mathrm{abscos\_x\_newn}}(l)
=
\left|S_v^{\cos}(l)\right|\times S_v^{\mathrm{new\_norm}}(l).
\]

该公式结合新旧知识视觉梯度方向关系强度与新知识视觉梯度幅值，不区分同向或反向，不加入深度权重，直接预测Adapter插入层，不做Pre-shift。

### 3.3 第二阶段如何使用定位结果

- 不得使用第二阶段最终test结果在Top-K中选择编辑层；
- 主实验优先采用Ours-Direct Top-1；
- 若必须在Top-3中选层，只能使用独立validation；
- 真实扫层最佳层仅作为Oracle分析，不得成为正式方法的输入；
- MMKE-Entity × BLIP2的Ours-Direct候选为Top-3：L0、L1、L2，可作为首个试点；若没有独立validation，固定Top-1 L0。

### 3.4 第一阶段尚未完全收口的事项

- 少量LLaVA真实候选层训练/评测仍可能需要补齐；
- EVQA的VisEdit严格KeyToken口径、LGA/CMA低覆盖问题及显著性检验仍需最终核验；
- 第二阶段可以先做独立小规模可行性试验，但不能将未完成组合写成已经完成。

## 4. 数据集事实与使用边界

### 4.1 MMKE-Entity

- 对应视觉实体知识编辑，`knowledge_type=entity_level`；
- `src`为编辑问题/提示，`pred`为数据集给出的原知识描述，`alt`为要注入的新知识描述；
- `alt`多数是人为构造的反事实知识，不能假定其在Wikidata中真实存在；
- train 636条，eval 955条；
- 每条样本的`port_new`长度均为1，且`port_type`均为`1-hop`；
- 可作为第二阶段知识图谱增强的主数据集，官方`port_new`用于评价一跳关联知识Portability。

### 4.2 MMKE-Visual

- 对应视觉语义编辑，`knowledge_type=visual_knowledge`；
- 主要编辑动作、手势、物体属性、物体关系或场景语义规则，而非稳定命名实体事实；
- train 214条，eval 293条；
- 每条样本的`port_new`长度均为1，`port_type`均为`1-hop`；
- `one_hop_img + port_new`主要评价编辑视觉语义能否应用于组合图像；
- `pred`可能为空，依赖旧知识时应使用冻结基础模型的确定性`model_pred`，不能静默填充；
- Wikidata对该子集的覆盖率可能有限，因此必须先做实体/概念链接覆盖审计，再决定纯Wikidata图还是受约束语义图。

### 4.3 E-VQA

- 现有使用版本没有`port_new`或其他Portability字段；
- 只能用于可靠性、普通文本/图像泛化和局部性保持验证；
- 不能用E-VQA直接支持“知识图谱提高关联知识传播”的主结论。

### 4.4 MMKE-Bench多跳结论

- MMKE-Entity和MMKE-Visual官方公开JSON只提供一跳Portability；
- 官方代码虽然预留`1-hop`至`4-hop`参数，但公开数据没有2/3/4-hop标注；
- 不得写成“MMKE-Bench官方包含多跳数据”；
- 若研究要报告2跳、3跳泛化，必须自行构建与MMKE编辑请求对齐的扩展评测集。

### 4.5 ReasonVQA

- ReasonVQA不是第二阶段必用数据集；
- 它可以提供`entity_id`、`property_id`、`hop`、`route`等多跳注释格式参考；
- 它缺少与MMKE编辑任务一一对应的`src/pred/alt`、编辑后可靠性和局部性标注；
- 直接在ReasonVQA上测准确率不能证明某条MMKE新知识在编辑后发生传播；
- 正式主实验不混入ReasonVQA。若使用，只能作为辅助格式参考、原始多跳能力诊断，或经严格转换后的扩展实验。

## 5. 第二阶段核心研究假设

- H1：相同编辑层和训练预算下，相关知识子图能够提高MMKE官方一跳Portability；
- H2：图结构编码应优于信息量相近的平铺三元组文本；
- H3：相关子图应优于等规模随机/无关子图；
- H4：Portability提升不应以明显损失Reliability、Generality或Locality为代价；
- H5：若构建2/3-hop扩展集，完整方法在更长推理路径上仍应优于Adapter-only。

本阶段主指标为Portability；Reliability与Locality作为必须同时满足的保持性指标，而不是把所有指标只压缩成一个平均分。

## 6. 借鉴GLAME但不直接照搬

第二阶段借鉴GLAME的两个思想：

1. Knowledge Graph Augmentation：围绕编辑目标构建局部关联子图；
2. Graph-based Knowledge Edit：使用关系感知图神经网络聚合实体与关系表示。

但本研究的编辑位置和参数化方式不同：

- 冻结基础VLM；
- 在第一阶段定位出的语言解码器视觉token位置插入Adapter；
- 目标知识和图谱知识都作为视觉表征残差注入；
- 不直接修改完整语言模型权重；
- 必须通过MMKE的编辑后指标验证。

## 7. 第二阶段正式结构约束

### 7.1 正确的双路融合

目标知识增量记为`ΔH_target`，图谱增量记为`ΔH_KG`。正式融合建议为：

\[
H'_v=H_v+\Delta H_{target}+\beta\Delta H_{KG},
\]

其中`β`为固定系数或样本相关可学习门控。

禁止分别计算`H_v+ΔH_target`和`H_v+ΔH_KG`后直接相加，否则原始表征会被重复为`2H_v`。

### 7.2 图谱向量注入

- 图节点/关系表示经过RGCN或同类关系感知GNN编码；
- 子图读出向量必须先投影到模型hidden size；
- 必须使用门控、Attention或token选择机制控制注入位置；
- 不建议将同一个未投影图向量无条件广播到全部视觉token；
- 需要记录每个模型的hidden size、视觉token span、hook层与张量shape。

### 7.3 冻结与可训练参数

原则上冻结：视觉编码器、对齐模块、语言模型主体参数。

允许训练：目标知识Adapter、图编码器/关系参数、图向量投影、门控或融合参数。所有可训练参数必须被显式列出，并统计参数量。

## 8. 知识图谱构建的关键约束

### 8.1 MMKE-Entity

1. 从图像实体、`src`、`pred`和`alt`抽取实体与关系候选；
2. 链接到Wikidata QID/PID，并保存候选、分数和人工复核状态；
3. 使用SPARQL检索限定关系集合内的一跳/二跳邻居；
4. 对节点数、边数、关系白名单、每跳分支数设置上限；
5. 缓存原始SPARQL结果，保证实验可复现；
6. 由于`alt`可能是反事实，必须在检索到的真实子图中覆盖或插入编辑根事实，再基于“编辑后图谱”定义问题答案；
7. 必须检测Wikidata真值与MMKE反事实冲突，不能把未修改的真实图谱直接称为编辑后知识。

### 8.2 MMKE-Visual

先审计Wikidata链接覆盖率。若动作/手势/规则无法稳定链接，可以构建受约束语义图，节点包括目标视觉概念、动作/属性、条件、对象和结果；但必须与MMKE-Entity的事实图分开命名和报告，不能假装所有语义图都来自Wikidata。

## 10. 定位贡献与图谱贡献的2×2实验

| 编辑层 | 无图谱 | 有图谱 |
|---|---|---|
| 对照定位层（Middle或VisEdit） | A | B |
| Ours定位层 | C | D |

- `C-A`：Ours定位贡献；
- `B-A`：对照层上的图谱贡献；
- `D-C`：Ours层上的图谱增量；
- D是否达到最佳综合效果。

层选择和图谱方法必须在测试前冻结，避免使用test结果进行事后选择。

## 11. 推荐最小可行性试验

首轮配置：

- 数据集：MMKE-Entity；
- 模型：BLIP2-OPT-2.7B；
- 编辑层：Ours Top-1 L0；若有独立validation，可在L0/L1/L2中选择；
- 组别：G0-G4；
- 流程：10条样本过拟合调试 → 100条样本小试 → 全量训练/独立评测；
- 随机种子：正式结论至少3个；
- 基础模型、训练epoch、batch size、学习率搜索预算和推理设置在组间保持一致。

建议放行条件：

- G3相对G1的Portability绝对提升至少3个百分点；
- G3优于G4；
- 三个随机种子的提升方向一致；
- Reliability、T-Loc和M-Loc相对G1下降不超过2个百分点；
- G3的提升不能完全由G2解释。

阈值需要在正式全量实验前冻结；若Claude提出修改，应明确说明修改依据。

```text
请先进行材料审计；若存在会改变实验主结论的关键信息缺失，列为“阻塞项”，不要自行假设。
```

## 18. 上下文超限时的操作

若出现`Conversation exceeds the length limit`：

1. 不在原对话继续反复提交；
2. 先保存已经生成的有用结果；
3. 新建对话；
4. 只上传第16节中的前三项；
5. 先让Claude输出“材料审计与缺失项”，不要第一轮就生成超长最终手册；
6. 第二轮根据审计结果，仅补充真正缺失的文件片段；
7. 第三轮再要求输出完整手册；
8. 若使用Claude Code且当前会话仍能响应，可先执行`/compact`；已经连续返回400时，直接新建会话更稳妥。

推荐采用三轮法：事实审计 → 缺口补充 → 最终手册。这样“信息是否齐全”由材料路由保证，而不是靠一次性上传所有原文保证。
