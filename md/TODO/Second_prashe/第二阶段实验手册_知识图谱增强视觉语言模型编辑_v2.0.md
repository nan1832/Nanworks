## 0. 总体研究目标与约束

### 0.1 核心研究问题

在第一阶段确定的视觉 Adapter 插入层上，通过引入编辑诱导的外部知识图谱，验证：

1. 相关知识子图能否提高 MMKE 官方 1-hop Portability；
2. 图结构编码是否优于无图 Adapter、平铺三元组和等规模随机图；
3. Portability 提升是否以牺牲 Reliability、Generality、Locality 为代价。

### 0.2 方法边界

**借鉴 GLAME**：
- 围绕编辑目标构建局部关联子图
- 使用 RGCN 融合实体与关系信息

**区别于 GLAME**：
- 编辑视觉语言模型，非纯文本 LLM
- 在语言解码器视觉 token 位置插入 Adapter，非 FFN 秩一更新
- 目标知识与关联知识均作为视觉表征残差注入
- 必须通过 MMKE 编辑后指标验证

### 0.3 固定实验决定

| 决定项 | 取值 |
|---|---|
| 首轮模型 | BLIP2-OPT-2.7B |
| 首轮数据集 | MMKE-Entity |
| 首轮编辑层 | Ours-Direct Top-1 **L0** |
| 官方 train 划分 | 80% dev_train + 20% dev_val（分层抽样） |
| 官方 eval | 保持为最终 test，禁止用于选层/选超参/选 checkpoint |
| 随机种子 | 试点 42，正式 [42, 2023, 2024] |
| 反事实处理 | 混合编辑图（真实邻域 + 插入编辑边 + 虚拟节点） |
| 多跳 Portability | 官方仅 1-hop；2/3-hop 需自建扩展测试集 |

### 0.4 冻结参数

- 视觉编码器（EVA-CLIP ViT）
- Q-Former
- 语言模型主体（OPT-2.7B 除编辑层外的所有层）

### 0.5 可训练参数

- 目标知识 Adapter（下投影 + 上投影 + LayerNorm）
- 图编码器（RGCN 权重、关系嵌入、basis 分解）
- 图向量投影（图隐藏维度 → 语言模型隐藏维度）
- Influence Mapper（门控网络，计算 $C_{KG}$）
- 融合系数 $\beta$（可学习标量或固定超参）

#### 步骤 2：视觉 Token Span 探测

```python
# 继续 p0_audit_blip2_interface.py

from PIL import Image

# 加载测试图像
image = Image.open("mmke_entity/train/entity/Secret (South Korean group)+12.jpg")
image_tensor = vis_processors["eval"](image).unsqueeze(0).to(model.device)

# 构造文本输入
prompt = "Give me some important information about the musical group in the image."
text_input = model.opt_tokenizer(prompt, return_tensors="pt").to(model.device)

# 前向传播
with torch.no_grad():
    image_embeds = model.ln_vision(model.visual_encoder(image_tensor))
    image_atts = torch.ones(image_embeds.size()[:-1], dtype=torch.long).to(model.device)
    
    query_tokens = model.query_tokens.expand(image_embeds.shape[0], -1, -1)
    query_output = model.Qformer.bert(
        query_embeds=query_tokens,
        encoder_hidden_states=image_embeds,
        encoder_attention_mask=image_atts,
        return_dict=True,
    )
    
    inputs_opt = model.opt_proj(query_output.last_hidden_state)
    atts_opt = torch.ones(inputs_opt.size()[:-1], dtype=torch.long).to(model.device)
    
    # 文本嵌入
    text_embeds = model.opt_model.get_input_embeddings()(text_input.input_ids)
    
    # 拼接
    inputs_embeds = torch.cat([inputs_opt, text_embeds], dim=1)
    attention_mask = torch.cat([atts_opt, text_input.attention_mask], dim=1)

print(f"Visual Token Span: [0, {inputs_opt.shape[1]})")
print(f"Text Token Start: {inputs_opt.shape[1]}")
print(f"Total Sequence Length: {inputs_embeds.shape[1]}")
```

**验收条件**：
- 确认视觉 token 数量（预期 32）
- 确认视觉 token 在序列开头 `[0, 32)`
- 记录文本 token 起始位置

#### 步骤 3：Hook 位置确定

```python
# 测试 hook 语义

def hook_fn(module, input, output):
    print(f"Hook triggered: input shape {input[0].shape}, output shape {output[0].shape}")
    return output

# 注册 hook 到第 0 层（L0）
target_layer = lm.model.decoder.layers[0]
handle = target_layer.register_forward_hook(hook_fn)

# 前向传播
with torch.no_grad():
    outputs = lm(
        inputs_embeds=inputs_embeds,
        attention_mask=attention_mask,
    )

handle.remove()

print(f"L0 corresponds to: model.decoder.layers[0]")
print(f"Input to L0: post-embedding, shape {inputs_embeds.shape}")
```

**验收条件**：
- Hook 成功触发
- 确认 L0 对应 `model.decoder.layers[0]`
- 确认输入是嵌入后的表征（非 logits）

#### 步骤 4：Adapter 零初始化等价性测试

```python
# scripts/test_adapter_identity.py

class VisualAdapter(torch.nn.Module):
    def __init__(self, hidden_size, bottleneck_size=256):
        super().__init__()
        self.down_proj = torch.nn.Linear(hidden_size, bottleneck_size)
        self.activation = torch.nn.ReLU()
        self.up_proj = torch.nn.Linear(bottleneck_size, hidden_size)
        self.layer_norm = torch.nn.LayerNorm(hidden_size)
        
        # 零初始化上投影
        torch.nn.init.zeros_(self.up_proj.weight)
        torch.nn.init.zeros_(self.up_proj.bias)
    
    def forward(self, hidden_states, visual_token_mask):
        """
        hidden_states: [batch, seq_len, hidden_size]
        visual_token_mask: [batch, seq_len] (1 for visual tokens, 0 for text)
        """
        adapter_output = self.up_proj(self.activation(self.down_proj(hidden_states)))
        adapter_output = adapter_output * visual_token_mask.unsqueeze(-1)
        return hidden_states + self.layer_norm(adapter_output)

# 测试
adapter = VisualAdapter(hidden_size=lm.config.hidden_size)
visual_mask = torch.zeros(1, inputs_embeds.shape[1])
visual_mask[:, :32] = 1  # 前 32 个是视觉 token

with torch.no_grad():
    original_output = lm(inputs_embeds=inputs_embeds, attention_mask=attention_mask)
    
    # 插入 Adapter（应该不改变输出）
    modified_embeds = adapter(inputs_embeds, visual_mask)
    adapter_output = lm(inputs_embeds=modified_embeds, attention_mask=attention_mask)
    
    diff = (original_output.logits - adapter_output.logits).abs().max().item()
    print(f"Max logits difference: {diff}")
    assert diff < 1e-5, "Adapter not identity-initialized!"
```

**验收条件**：
- 零初始化 Adapter 输出与原模型一致（差异 < 1e-5）
- 确认 `visual_token_mask` 正确屏蔽文本 token

#### 步骤 5：梯度流检查

```python
# scripts/test_gradient_flow.py

# 冻结基础模型
for param in model.visual_encoder.parameters():
    param.requires_grad = False
for param in model.Qformer.parameters():
    param.requires_grad = False
for param in lm.parameters():
    param.requires_grad = False

# 解冻 Adapter
adapter = VisualAdapter(hidden_size=lm.config.hidden_size)
for param in adapter.parameters():
    param.requires_grad = True

# 虚拟损失
modified_embeds = adapter(inputs_embeds, visual_mask)
outputs = lm(inputs_embeds=modified_embeds, attention_mask=attention_mask)
loss = outputs.logits.sum()
loss.backward()

# 检查梯度
frozen_params_with_grad = []
for name, param in lm.named_parameters():
    if param.grad is not None and param.grad.abs().sum() > 0:
        frozen_params_with_grad.append(name)

assert len(frozen_params_with_grad) == 0, f"Frozen params have gradients: {frozen_params_with_grad}"

trainable_params_without_grad = []
for name, param in adapter.named_parameters():
    if param.grad is None or param.grad.abs().sum() == 0:
        trainable_params_without_grad.append(name)

# 允许 LayerNorm 在零初始化时梯度为零
if trainable_params_without_grad:
    print(f"Warning: Trainable params without gradients: {trainable_params_without_grad}")
```

**验收条件**：
- 冻结模块无梯度
- Adapter 下投影、激活、上投影有梯度
- 梯度仅流向新增模块

## P2：MMKE-Entity 实体链接与子图构建

### 目标

为每条编辑样本构建混合编辑图：真实 Wikidata 邻域 + 反事实编辑边 + 虚拟节点。

### 输入

- `mmke_entity/dev_train.json`
- Wikidata SPARQL 端点
- 预训练 NER 模型（spaCy 或 Flair）

### 操作步骤

#### 步骤 1：编辑三元组提取

提取主体实体和编辑关系，对比 pred 和 alt 识别被修改的事实。

**验收条件**：
- 至少提取出 80% 样本的主体类型
- 至少识别出 50% 样本的编辑关系（location/member/attribute）

#### 步骤 2：实体链接

使用 Wikidata API 搜索，链接主体实体和新对象到 QID。

**验收条件**：
- 主体实体链接覆盖率 ≥ 80%
- Top-1 候选人工抽查准确率 ≥ 90%（抽查 50 条）
- 新对象能链接的比例 ≥ 60%（反事实可能无法链接）

#### 步骤 3：混合编辑图构建

1. 获取主体的 Wikidata 邻域（SPARQL 查询）
2. 识别冲突边并标记
3. 插入编辑边（真实 QID 或虚拟节点）

**验收条件**：
- 每个样本至少有 1 条编辑边
- 真实节点比例 = 能链接的对象数 / 总对象数
- 虚拟节点有明确的文本描述（用于初始化）

#### 步骤 4：人工审核

抽样 50 条进行人工审核，确认主体链接、对象链接和图结构合理性。

**验收条件**：
- 主体链接准确率 ≥ 90%
- 新对象链接准确率 ≥ 85%（排除无法链接的样本）
- 图结构合理率 ≥ 95%

### 输出

**图谱文件**：
- `subgraphs/mmke_entity/dev_train/{sample_id}.json`
- 每个文件包含：`nodes`、`edges`、`root`、`metadata`

**统计报告**：`reports/p2_entity_linking_report.md`

### 失败回退

**问题 1**：实体链接准确率 < 80%
- **回退**：放宽类型约束，增加候选数至 Top-10，人工标注 Top-1

**问题 2**：虚拟节点比例过高 (> 50%)
- **回退**：保留虚拟节点，在图编码时使用文本编码器初始化

**问题 3**：冲突边识别失败
- **回退**：手动构建关系映射表（文本描述 -> Wikidata Property ID）

## P3：Adapter-only 基线复现（G1）

### 目标

在固定编辑层 L0 上复现第一阶段 Adapter-only 性能，建立第二阶段的公平基线。

### 输入

- `mmke_entity/dev_train.json`
- `mmke_entity/dev_val.json`
- `mmke_entity/official_test.json`
- P0 审计的模型接口

### 核心组件

#### 数据加载器

构建 MMKEEntityDataset，加载图像、文本、标签和评估字段。

#### Adapter 模型

VisualAdapterEditor 在编辑层插入视觉 Adapter，冻结基础模型。

#### 训练循环

- 优化器：AdamW，学习率 5e-5
- 调度器：线性 warmup
- 训练轮数：10-15 epochs
- 损失：目标文本的负对数似然

#### 评估指标

1. **Reliability**：编辑成功率（能否生成 alt）
2. **Portability**：1-hop 泛化（port_new 问题正确率）
3. **Text Locality**：无关文本知识保持
4. **Multimodal Locality**：无关多模态知识保持
5. **Text Generality**：rephrase 泛化
6. **Multimodal Generality**：image_rephrase 泛化

### 验收条件

- Reliability ≥ 60%（能够编辑目标知识）
- Portability ≥ 30%（基线水平）
- Locality ≥ 80%（保持无关知识）

### 输出

**模型权重**：
- `checkpoints/mmke_entity/blip2/adapter_only/seed42/best.pt`

**评估结果**：`results/g1_adapter_only.json`

### 失败回退

**问题 1**：训练损失不下降
- **回退**：降低学习率至 1e-5，增加 warmup 步数

**问题 2**：Reliability < 50%
- **回退**：增大 max_length，使用更大的 bottleneck_size

**问题 3**：Portability 接近 0
- **回退**：人工审核 20 条失败样本，分析原因

## P4：RGCN 图编码与知识注入

### 目标

实现 GLAME 风格的图编码器和融合模块，构建完整方法 G3。

### 输入

- P2 构建的混合编辑图
- P3 训练好的 Adapter 权重（作为初始化）
- GLAME 论文中的 RGCN 配置

### 核心组件

#### 1. 图数据结构

**HybridGraphEncoder**：
- 节点初始化：使用 BERT 编码节点标签文本
- RGCN 层：2 层关系图卷积网络，支持多种关系类型
- 根节点提取：提取主体实体的表征作为图向量

#### 2. Influence Mapper

计算门控 $C_{KG} \in [0,1]^{N_v \times 1}$：
- 输入：视觉表征 $H_v$、问题表征 $q$、图表征 $z_G$
- 输出：每个视觉 token 的门控值
- 结构：3 层全连接网络 + Sigmoid

#### 3. 完整融合模型

**GraphAugmentedEditor**：

```
1. 目标知识增量：ΔH_target = TargetAdapter(H_v)
2. 图知识增量：ΔH_KG = gate ⊙ GraphProj(RGCN(graph))
3. 融合：H_v' = H_v + ΔH_target + β·ΔH_KG
```

#### 4. 损失函数

```
L = L_edit + λ_loc·L_loc + λ_gate·L_gate + λ_norm·L_norm
```

- **L_edit**：目标文本的负对数似然
- **L_loc**：训练集 locality 样本的 KL 散度
- **L_gate**：门控稀疏正则（L1）
- **L_norm**：增量范数正则

### 验收条件

- RGCN 前向传播成功
- 图向量维度正确（768 -> 2560）
- 门控值在 [0, 1] 范围内
- 融合后序列长度不变
- 梯度正常流动

### 输出

**模型权重**：
- `checkpoints/mmke_entity/blip2/graph_augmented/seed42/best.pt`

**中间输出**（调试用）：
- 每个样本的根节点向量
- 门控值分布
- β 的训练曲线

### 失败回退

**问题 1**：RGCN 输出全零
- **回退**：使用 GCN 代替 RGCN（忽略关系类型）

**问题 2**：门控全 0 或全 1
- **回退**：添加梯度裁剪，调整初始化

**问题 3**：图向量投影后梯度消失
- **回退**：移除 LayerNorm，使用 Dropout

## P5：对照组实验（G0, G2, G4, G5）

### 目标

实现公平对照组，验证图结构和目标知识选择的贡献。

### G0：Base VLM

直接使用未编辑的 BLIP2，作为零样本基线。无需训练，直接评估。

**预期**：Reliability ≈ 0（输出旧知识），Portability ≈ 随机

### G2：Adapter + FlatTriples

将图谱三元组拼接成文本，用文本编码器编码后注入。

**关键**：
- 将边转为 "head relation tail" 文本
- 使用 BERT 编码拼接后的文本
- 无图结构编码

**验收条件**：
- 图谱信息量与 G3 相同（相同的节点和边）
- 参数量近似（文本编码器 vs RGCN）

### G4：Adapter + RandomGraph

构造等规模随机图，控制图结构的贡献。

**关键**：
- 随机节点标签（"RandomEntity0", "RandomEntity1", ...）
- 随机边（保持与真实图相同的节点数、边数、关系数）
- 无语义信息

**验收条件**：
- 随机图与真实图的节点数、边数、关系数完全匹配
- 随机图无语义信息

### G5：Adapter + RGCN w/o Influence Mapper

移除 Influence Mapper，图向量均匀注入所有视觉 token。

**关键**：
- gate = 1（全 1 门控）
- 其他组件与 G3 完全相同

**验收条件**：
- G5 与 G3 的唯一区别是门控机制
- 参数量略少（无 Influence Mapper）

### 输出

**对照组结果表**：`results/ablation_study.csv`

### 失败回退

**问题**：G2 性能意外高于 G3
- **排查**：检查 G3 的 RGCN 是否训练充分、图质量是否有问题
- **回退**：增加 RGCN 层数，调整学习率

## P6：小规模可行性验证（Pilot）

### 目标

在 10 样本调试 + 100 样本试点上验证整个流程，避免全量训练失败。

### 步骤 1：10 样本调试

选择 10 条样本，快速迭代 3 个 epoch。

**验收条件**：
- 3 个 epoch 内能记住 10 条样本（过拟合测试）
- 输出长度正常（非空、非重复）

### 步骤 2：100 样本试点

80 条训练，20 条验证，训练 G1, G3, G4。

**验收条件**：
- G3 Portability > G1 Portability（至少在验证集上）
- G3 Portability > G4 Portability
- 无 NaN、梯度爆炸、OOM

### 输出

**Pilot 报告**：`reports/pilot_100_results.md`

**放行条件**：
- ✓ G3 优于 G1 和 G4
- ✓ 无工程阻塞问题
- → 批准进入全量训练

### 失败回退

**问题**：Pilot 阶段 G3 未优于 G1
- **诊断**：
  - 检查 100 样本中图谱质量（实体链接覆盖率）
  - 检查 Portability 问题是否真的依赖图谱
  - 人工审核 20 条失败样本
- **回退**：
  - 若图谱质量问题 → 回 P2 改进链接策略
  - 若 RGCN 未学习 → 调整超参数、增加层数
  - 若 Port 问题本身不依赖图谱 → 重新审视数据集选择

```python
for seed in seeds:
    set_seed(seed)
    for group in groups:
        # 训练或评估
        # 在 dev_val 上选择最佳 checkpoint
        # 在 official_test 上最终评估
```

### 步骤 3：评估指标完整版

1. **Reliability**：编辑成功率
2. **Portability**：1-hop 泛化
3. **Text Generality**：rephrase 泛化
4. **Multimodal Generality**：image_rephrase 泛化
5. **Text Locality**：无关文本知识
6. **Multimodal Locality**：无关多模态知识

### 步骤 4：统计显著性检验

- Bootstrap 95% 置信区间
- 配对 t 检验（G3 vs G1, G3 vs G4）
- Holm 校正（多重比较）

### 输出

**最终结果表**：`results/final_results_mmke_entity_blip2.csv`

**统计分析报告**：`reports/statistical_significance.md`

### 验收条件

**核心结论成立**：
1. ✓ G3 Portability > G1 Portability（p < 0.05，Δ ≥ 3pp）
2. ✓ G3 Portability > G4 Portability（p < 0.05）
3. ✓ G3 Portability 不能完全被 G2 解释（G3 > G2）
4. ✓ G3 Reliability、Locality 不显著下降（p > 0.05 或 Δ < 2pp）

### 失败回退

**问题 1**：G3 Portability 未显著高于 G1（p > 0.05）
- **诊断**：
  - 检查 3 个种子是否有一致的趋势（至少 2/3 支持）
  - 检查 Port 问题中依赖图谱的比例（人工标注 50 条）
- **回退**：
  - 若趋势一致但差距小 → 增加样本量或放宽显著性阈值（p < 0.1）
  - 若趋势不一致 → 检查随机种子是否影响子图质量

**问题 2**：G3 Locality 显著下降 (> 5pp)
- **回退**：增大 λ_loc 权重，在 Locality 样本上显式训练保持原分布

## P8：多跳 Portability 扩展测试（KGPort-Edit）

### 目标

构建 2-hop 和 3-hop 测试集，验证编辑知识是否沿确定路径传播。

### 输入

- P2 构建的子图（包含 2-3 跳路径）

### 操作步骤

#### 步骤 1：路径采样

从根节点采样 2-hop 和 3-hop 路径：
- 找出编辑边（source == "edit"）
- 从新对象出发的 Wikidata 边
- 构造问题模板

#### 步骤 2：问题生成

根据路径生成问题，确保：
- 问题依赖编辑后的根边
- 基础模型无法回答（需要编辑）
- 答案唯一且可验证

#### 步骤 3：人工审核

抽查 50 条，确认问题质量：
- `requires_edit`: 问题是否必须依赖编辑后知识
- `answer_unique`: 答案是否唯一可验证
- `gold_route_correct`: gold route 是否正确

#### 步骤 4：评估

在 G1, G3, G4 上评估多跳性能：
- Port@1：1-hop 正确率
- Port@2：2-hop 正确率
- Port@3：3-hop 正确率

### 输出

**扩展测试集**：
- `kgport_edit/mmke_entity_2hop.json`（~300 条）
- `kgport_edit/mmke_entity_3hop.json`（~100 条）

**多跳结果**：`results/multihop_portability.csv`

### 失败回退

**问题**：2-hop 问题生成质量低
- **回退**：减少自动生成比例，增加人工编写模板
