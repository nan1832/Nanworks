## 3. 顺序调整及原因

v2.1手册把已验收`dev_train.json`列为P2输入；当前P1只有508/128候选，未验收原因正是主体/事实身份缺失。如果先冻结dev再链接身份，会形成循环依赖。

实际顺序调整为：

1. 官方train 636条全量抽取主体候选；
2. 固定50条进行Wikidata候选检索；
3. 审核候选链接并冻结可靠QID；
4. 抽取/映射编辑关系与新旧对象，形成事实根；
5. 将主体QID、事实根与图片身份合并为连通分量；
6. 重新执行一次固定seed的80/20组划分并验收；
7. 只对验收后的dev构建Wikidata混合子图。

该调整不改变P2研究目标，只补上手册原先假定已存在的结构化身份层。

## 4. 阶段计划

### P2-A：主体候选抽取

- 从`alt`锚点句提取自然语言主体；
- 同时记录`type_self`、稳定sample ID和源记录索引；
- 对`pred/alt`生成审计用词法差异，不把差异直接宣称为关系三元组；
- 全量输出`subject_extraction_all.jsonl`。

验收：636条均有候选主体；类型与锚点句一致；候选名称唯一性只作统计。

### P2-B：Wikidata 50条固定pilot

- 用`sha256(seed + NUL + stable_sample_id)`稳定排序选50条；
- seed固定为`20260917`，不反复挑选；
- 每条保存Top-10候选、标签、描述、API顺序和本地评分；
- 自动Top-1始终标记`review_required`；
- 生成带空白人工判定列的`entity_linking_review.csv`。

验收：查询完成率、候选覆盖率和精确标签比例可统计；准确率必须在审核后计算。

### P2-C：主体QID审核与全量链接

- 复查50条Top-1，错误时从Top-10选择或标记未链接；
- 分析错误类型：别名、同名消歧、类型不符、搜索缺失；
- 只有审核准确率达到手册门槛后才扩到636条；
- 全量阶段为每条记录保存候选、置信依据和审核状态。

### P2-D：关系、新旧对象和事实根

- 以`pred`为旧描述、`alt`为新描述；
- 将差异映射为零个或多个候选关系，不强迫单事实；
- 可链接对象保存QID，反事实文字或数值保存显式虚拟节点；
- 事实根至少包含：主体QID、关系P-ID或受控关系标签、旧对象、新对象；
- 多事实样本保留多条根边和共同样本ID。

### P2-E：重建连通分组并验收dev

- 连接键：主体QID、事实根ID、图片路径、图片内容哈希；
- 所有共享任一身份的样本形成同一连通分量；
- seed仍固定，official eval不参与划分；
- 输出正式`dev_train.json`、`dev_val.json`、`split_manifest.json`的前提是身份缺口和巨大分量检查通过。

### P2-F：混合编辑图

- 只对正式dev构建；
- 使用静态Wikidata缓存，评测时禁止动态查询；
- 加入真实邻域、反事实根边和必要虚拟节点；
- 不读取Portability问题答案；
- 保存图来源、查询时间、QID/PID、虚拟节点和失败原因。
